# Audit: v1.3.0 — Real Source (Final)

**Audit status:** Superseded by corrective release v1.3.1  
**Audited artifact:** Environmental Studies Android v1.3.0 source tree  
**Purpose:** Preserve the final source-level audit, distinguish it from the earlier stale-APK review, and record the disposition of every finding.

## Scope correction

The v1.3.0 source was substantially newer than the compiled APK reviewed previously: the APK's `index.html` was 87,333 bytes, while the source file was 98,125 bytes. Findings based on the stale APK are therefore superseded wherever they conflict with this source-level audit. The verifier scripts were executed against the source tree, and the expanded `MainActivity.java` was traced directly.

## Blocking CI defect — confirmed

The two source verifiers gave opposite results because they targeted different releases:

```text
$ python3 tools/verify_content_integrity.py
VERIFY FAIL: hash unit-01.html; bytes unit-01.html; ... catalog; gradle version

$ python3 tools/verify_content_integrity_v130.py
VERIFY PASS: v1.3.0 content hashes, 46-lesson academic-depth gates,
English-first/Tamil-second ordering, 58 bilingual MCQs, catalog,
navigation bridge, reader-height and Android release invariants verified.
```

The first script was still tied to the v1.2.3 manifest. The v1.3.0-aware script passed, but CI invoked the stale script:

```yaml
- name: Verify content revision and catalog
  run: python tools/verify_content_integrity.py
```

This guaranteed failure before Gradle started.

**v1.3.1 disposition:** Resolved. The dual-verifier state was removed. One canonical `tools/verify_content_integrity.py` now validates the current release, and CI invokes that exact file.

## Architecture pivot — accepted

`MainActivity.java` grew from roughly 4.6 KB to 8.3 KB because the reader architecture changed, not because of accidental bloat:

- Native Android buttons now drive Contents, previous/next navigation, figure focus, Privacy, English, Tamil and combined EN+TA presentation.
- The buttons invoke the existing page functions through `evaluateJavascript()`.
- A native `ScrollView` owns vertical scrolling while the WebView renders bundled educational content.
- The earlier overlapping handset CSS experiments were consolidated into one authoritative mobile layer.
- `HostBridge.setContentHeight()` reports rendered height from JavaScript to Android after navigation and language changes, preventing the WebView-inside-ScrollView clipping problem.

This is a sound response to the device-specific failures of transform-based WebView pagination and animated page turns.

**v1.3.1 disposition:** Retained and formally documented in `docs/adr/0001-native-handset-reader.md`.

## JavaScript interface — acceptable, constrained trade-off

`addJavascriptInterface()` is present again, so the earlier "zero JS–Java bridge" security claim no longer applies. The practical risk remains low because:

- `minSdk` is 24, above the API 17 boundary associated with the historic reflective-exposure vulnerability;
- only one `@JavascriptInterface` method is exposed;
- that method accepts an integer and only adjusts view height;
- all content is bundled and served from the controlled local asset origin;
- external navigation remains blocked; and
- the manifest contains no INTERNET permission.

The bridge is therefore acceptable for this specific UI-sizing purpose. It must not become a general-purpose command channel.

**v1.3.1 disposition:** Guarded by source verification. The verifier requires exactly one annotated bridge method, and the ADR requires explicit security review before any future bridge expansion.

## README version drift — confirmed

The v1.3.0 source contained three conflicting identities:

- README title: v1.2.4
- README metadata: versionName 1.2.6 / versionCode 10206
- `app/build.gradle`: versionName 1.3.0 / versionCode 10300

This was the third consecutive release with README drift.

**v1.3.1 disposition:** Resolved. README, Gradle and catalog metadata are synchronized to versionName 1.3.1 / versionCode 10301. The canonical verifier now fails CI if they diverge, eliminating silent drift.

## Confirmed fixes already present in v1.3.0

- `tools/requirements.txt` pins `beautifulsoup4==4.13.4`.
- CI installs verifier dependencies before verification.
- CI artifact naming is derived dynamically from Gradle metadata.
- `android:enableOnBackInvokedCallback="true"` remains enabled.
- No INTERNET permission is declared.
- Edge-to-edge inset handling was consistently removed after adopting `setDecorFitsSystemWindows(true)`.

## Figure-focus control — assessed

The former `▣ Visual` button called a real `toggleVisualFocusNative()` function. It was functional but opaque: the label did not tell students that the control isolates figures and explanatory visual material.

**v1.3.1 disposition:** Renamed to `▣ Figures`. When active, the label changes to `▣ Full`, making the two states discoverable. Pages without a visual return a clear "No visual on this page" message.

## Final resolution

The v1.3.0 native-shell architecture was retained. The blocking CI mismatch, release-metadata drift and opaque figure-control label were corrected in v1.3.1. The height bridge remains deliberately narrow and audited. No unresolved structural objection from this source audit remains; physical-device scrolling, touch behavior and rendering are still release-acceptance tests rather than properties that static source or CI can prove.
